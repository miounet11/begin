# 例子：方案制定

服从 FAMILY.md · 角色：例子，不是现行产品合同。

本页演示如何从一句短做成跑 [practices/formulate.md](../practices/formulate.md)，产出开工包。

---

## 输入

owner 给的短做成：

> 用户交一份原创乐谱规格，得到一首能播的歌，同一份谱可换模型重演。

散乱笔记：

- 想做音乐生成
- 竞品有 Suno、Udio
- 本地优先？还是云端？

---

## F1 确认做成句

| 检查 | 结果 |
|------|------|
| 现在时 | ✓「得到一首能播的歌」 |
| 能写成测试 | ✓ 主路径：提交谱 → 等待 → 播放 |
| 说用户完成的事 | ✓ 不是「做个 App」 |
| 不含通道清单 | ✓ 没有「Win + Mac + iOS + Android」 |

做成句确认：**用户交一份原创乐谱规格，得到一首能播的歌，同一份谱可换模型重演。**

---

## F2 北极星

1. 作品的权威在词曲谱（用户创作的是谱，不是模型输出）
2. 模型可替换（不锁定单一模型）
3. 主路径能播（用户能听到结果）

---

## F3 主柱

| 主柱 | 现在几分 | 判定方式 |
|------|----------|----------|
| 谱对 | 未测 | 提交谱 → 生成 → 和谱逐轨对比，错位率 < 5% |
| 能播 | 未测 | 主路径完成率 > 95%（提交 → 等待 → 播放） |
| 换模型重演 | 未测 | 同一份谱换模型，输出结构一致 |

产品力 = min(谱对, 能播, 换模型重演)。

---

## F4 竞品扫描

| 竞品 | 用户 job | 主路径 | 学到什么 | 不抄什么 | 证据 |
|------|----------|--------|----------|----------|------|
| Suno | 用一句话得到一首歌 | 输入描述 → 等待 → 播放 | 主路径 < 3 步；等待时有进度 | 歌词生成（我们用户自己写谱） | suno.ai |
| Udio | 用描述控制音乐风格 | 输入描述 → 调参数 → 等待 → 播放 | 失败时告知原因；可重试 | 复杂参数面板（我们用谱代替参数） | udio.com |

**结论**：

- 北极星已覆盖：主路径能播、作品权威在谱
- 新增不做：歌词生成、复杂参数面板、受版权保护的词曲
- 新增门禁：主路径 < 3 步、失败时告知原因

---

## F5 技术选型

主路径：用户提交谱 → 调用模型生成 → 返回可播音频。

| 方案 | 能做成什么 | 代价 | 锁定 | 失败样子 |
|------|-----------|------|------|----------|
| A: 本地优先 + 本地模型 | 离线可用、隐私 | 大模型需要高配显卡 | 用户必须有 GPU | 低配用户无法使用 |
| B: 云端模型 API | 任何设备可用 | API 成本、网络依赖 | 锁定云厂商 | API 超时、欠费停服 |
| C: 混合（本地谱处理 + 云端生成） | 平衡离线和低配 | 两套代码 | 部分锁定云厂商 | 网络断开时功能降级 |

**选：方案 B（云端模型 API）**

理由：L0 先验证主路径能跑，低配用户也能用；等 L1 再考虑本地降级。

**延后**：

| 事项 | 为什么延后 | 什么条件下再谈 |
|------|------------|----------------|
| 本地模型支持 | 还在 L0 | 主路径能跑 + 升到 L1 |
| 多模型切换 UI | 先验证换模型机制 | 换模型测试通过 |
| 多端客户端 | 还在 L0 | 升到 L2 且主柱过线 |

## F7 填开工信

### 第一轮七步计划

| 步骤 | 内容 |
|------|------|
| 诊断 3 缺口 | 1. 没有谱格式规范 2. 没有模型调用 3. 没有播放器 |
| 规格不变量 | 提交谱 → 返回可播音频；失败时返回错误原因 |
| P0 | 实现主路径：提交谱 → 调用一个模型 → 返回音频 |
| 先红灯 | 写一个测试：提交样例谱，期望返回音频，当前失败 |
| 最小绿 | 实现谱解析 + 模型调用 + 返回音频，让测试通过 |

- API 成本预算
