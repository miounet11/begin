填写指南：

- **方案**：技术路线名称（如「本地优先 + SQLite」「云函数 + PostgreSQL」）
- **能做成什么**：这条路能让哪些北极星 / 主柱变绿
- **代价**：开发成本、运维成本、学习成本、依赖成本
- **锁定**：选了这条路后难以改变的决定（如「选了云厂商 X 就难迁到 Y」）
- **失败样子**：这条路失败时用户会感知到什么（如「主路径超时」「数据丢失」）

## 常见错误

| 错误 | 修法 |
|------|------|
| 列了 10 条方案 | 只保留 2–4 条真实可选的 |
| 方案是「用最好的技术」 | 改成具体技术栈名称 |
| 没有「失败样子」 | 每条方案必须写失败时用户感知到什么 |
| 没有选择理由 | 必须写一句话解释为什么选这条 |
| 延后事项是空的 | 至少写一条「本轮不做」的技术事项 |
| 包含密钥或 token | 删除，密钥不进仓 |
| 为全端选型 | 只为 P0 主路径选，其余延后 |
